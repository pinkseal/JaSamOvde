# Я здесь · Seal&Tea

Личный кабинет с логином и паролем, отметками присутствия по этажам,
приглашениями с комментариями и шкалой визитов — для Seal&Tea.

Это отдельное веб-приложение (Next.js), которое разворачивается на Vercel
со своей базой данных Postgres. Пароли хранятся как bcrypt-хеши на сервере —
это настоящая защита, в отличие от прежней версии внутри Claude.

## Что внутри

```
pages/api/       — серверные ручки (регистрация, вход, отметки, приглашения, комментарии)
lib/             — подключение к базе, сессии, вспомогательные функции
public/index.html — всё приложение целиком (вёрстка + логика), обращается к pages/api/*
schema.sql       — SQL-схема, которую нужно один раз выполнить в базе
```

## Деплой на Vercel, шаг за шагом

1. **Выложите проект на GitHub.**
   Создайте пустой репозиторий и запушьте туда содержимое этой папки.

2. **Импортируйте проект в Vercel.**
   На vercel.com → Add New → Project → выберите этот репозиторий → Deploy.
   Первый деплой пройдёт без базы данных — это нормально, приложение
   заработает после следующих шагов.

3. **Подключите базу данных.**
   В панели проекта на Vercel → вкладка **Storage** → **Create Database** →
   выберите **Postgres** (сейчас это делается через Neon — интеграция
   встроенная, ничего дополнительно регистрировать не нужно) → **Connect**
   к этому проекту. Vercel сам добавит переменные окружения `POSTGRES_URL` /
   `DATABASE_URL` — трогать их не нужно.

4. **Задайте секрет для сессий.**
   В **Settings → Environment Variables** добавьте переменную
   `SESSION_SECRET` — любая случайная строка не короче 32 символов.
   Получить такую можно командой в терминале:
   ```
   openssl rand -base64 32
   ```

5. **Выполните схему базы данных один раз.**
   Откройте вашу базу в **Storage → (ваша база) → Query** и вставьте
   содержимое файла `schema.sql`, затем выполните.

6. **Передеплойте проект.**
   После добавления переменных окружения нажмите **Redeploy** в списке
   деплоев (переменные подхватываются только при новой сборке).

7. **Откройте сайт.**
   Зайдите на `ваш-проект.vercel.app`, нажмите «Создать кабинет», введите
   логин и пароль — готово. С другого телефона под тем же логином и
   паролем откроется тот же профиль.

## Локальная разработка

```
npm install
cp .env.example .env.local   # впишите POSTGRES_URL и SESSION_SECRET
npm run dev
```

`POSTGRES_URL` для локальной разработки можно получить командой
`vercel env pull .env.local` после `vercel link` — тогда подтянутся те же
переменные, что и в проекте на Vercel.

## Как это устроено технически

- **Аутентификация** — cookie-сессия (`iron-session`), пароль хранится как
  bcrypt-хеш, никогда не передаётся обратно клиенту.
- **База данных** — Postgres через `@neondatabase/serverless`, 4 таблицы:
  `accounts`, `presence`, `invites`, `comments` (см. `schema.sql`).
- **Обновление данных в реальном времени** — не настоящий realtime, а опрос
  сервера каждые 4 секунды, пока открыта вкладка «Кафе» или «Приглашения».
  Для чайной такого масштаба этого достаточно; если нужен мгновенный
  realtime, это отдельная доработка (например, через Pusher или Ably).
- **Таймер «вы здесь уже»** не сбрасывается при смене этажа — сервер хранит
  исходное время отметки и обновляет только этаж/настроение.

## Известные ограничения

- Без модерации: любой вошедший может удалить только свои заявки, но
  комментарии удалить нельзя ни своему автору, ни бармену — при желании
  легко добавить.
- Логин используется как первичный ключ аккаунта (в нижнем регистре,
  только латиница/цифры/`_-.`), поэтому сменить логин самому нельзя —
  только завести новый кабинет.
- Восстановления пароля нет (нет отправки почты) — если пароль забыт,
  единственный выход сейчас — завести кабинет с другим логином.
